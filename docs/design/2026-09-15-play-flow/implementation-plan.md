## 2. 주사위와 게임 동작 유지 조건

시안의 `3 · 5`는 화면 배치를 보여주기 위한 임시 표기입니다. 실제 게임에 적용할 때 숫자만으로 주사위를 대체하지 않습니다.

- **일반 모드:** 입체 주사위 2개와 점 눈을 표시하고, 던짐·회전·튕김·착지 뒤 두 눈의 합만큼 말이 한 칸씩 이동합니다. `8칸 이동` 같은 합계는 보조 문구로 표시합니다.
- **진행 순서:** 버튼 입력 → 게임판 노출 → 주사위 던짐·구름 → 착지·눈 확인 → 말 이동 → 도착 → 기존 시장/생활사건 흐름. 일반 턴마다 새 팝업을 추가하지 않고 현재 중요 뉴스와 일반 안내의 차이를 유지합니다.
- **화면 이동:** 먼저 게임판을 보여 주고, 말 이동 중에는 매 프레임 다시 스크롤하지 않습니다. 사용자가 직접 스크롤하면 자동 스크롤을 중단하는 기존 동작을 유지합니다.
- **소리·속도:** 소리 켬/끔, 1배/2배 설정을 유지합니다. 기본 주사위 회전 1,120ms + 착지 대기 280ms를 먼저 보존합니다. 이 시간은 주사위 연출 구간이며 말 이동 시간은 별도입니다.
- **동작 줄이기:** 앱 설정 및 OS 설정을 존중해 긴 회전·점프를 생략합니다. 적용 시 정지된 주사위 눈과 합계 결과를 확인할 수 있도록 보완합니다. 이 정적 결과 표시 보완은 제안이며 현재 동작으로 검증된 것은 아닙니다.
- **정확성:** 실제 엔진이 정한 눈과 화면에 착지한 눈, 이동 칸 수가 일치해야 합니다. 애니메이션에서 별도 난수를 만들거나 턴을 두 번 진행시키지 않습니다.
- **중복·중단:** 연타·모달 전환·처음 화면 이동·새로고침으로 턴/운용/점수가 중복 처리되지 않아야 합니다. 종료한 장면의 타이머가 다음 판에 영향을 주면 안 됩니다.

현재 코드 근거: `src/ui/dice.ts` (입체 면·점 눈·시간), `src/styles/main.css` (회전·튕김 CSS), `src/ui/app.ts:917` 부근 (보드 노출→주사위→말 이동→startTurn), `src/ui/animation-controller.ts` (취소), `src/ui/board-viewport.ts` (스크롤), `src/ui/sound.ts` (소리). 이번 확인은 로컬 코드 검토이며 운영 사이트에서 새로 플레이한 결과는 아닙니다.

## 3. 먼저 정할 공통 기준

1. **한 가지 디자인 규칙:** A-1의 흰 배경·녹색 주요 버튼·파스텔 보조색을 색상, 글꼴, 숫자, 여백, 둥근 모서리, 버튼 상태의 공통 변수로 정리합니다. 손실·경고는 색 외에 기호와 문구로 구분합니다.
2. **PC와 모바일의 정보 순서:** 5번안은 PC에서는 좌우, 모바일에서는 위아래로 배치합니다. 금액 입력 → 미리보기 → 확정 순서, 문제 → 답안 → 해설 순서가 유지되도록 합니다. 정산은 요약 → 시장 변화/내 보유 영향 → 내 행동 순으로 읽게 합니다.
3. **상태까지 완성:** 각 시안의 정상·선택·비활성·오류·대기·완료 상태를 정의합니다. 초깃값만 예쁘게 보이는 화면으로 끝내지 않습니다. 거래불가 사유, 위험비중 안내, 미응답 퀴즈 안내는 기존 검증값을 사용합니다.
4. **캐릭터 자산 정리:** 메인·안내·완주용 올리·원이 자산의 해상도와 투명 배경을 정리하고, 실제 게임 말은 작은 크기에서도 식별되는 별도 표현으로 만듭니다. 투자성향과 캐릭터 외형은 분리합니다. 캐릭터 선택 기능과 기존 외형의 처리 범위도 적용 전에 결정 문서에 적습니다.
5. **기존 기능 목록과 대조:** 시안은 대표 상태를 보여주는 예시이므로 기존 상품/금액/필터/도움말/거래 가능 조건을 화면별로 대조합니다. 특히 일반 주문 5종과 포트폴리오 일반·디폴트·미결제 구분을 빠뜨리지 않습니다. 예시 금액과 진단 결과를 실제 데이터처럼 복사하지 않습니다.

## 4. 구현 순서 제안

단계별 변경·검증을 쌓고, 모든 화면이 연결된 뒤 운영판에 한 번에 배포하는 방식을 권장합니다. 중간 결과는 검토용 배포에서 확인합니다. 큰 변경 한 번으로 마무리하기보다 아래 순서로 나눕니다.

| 단계 | 적용 대상 | 작업과 완료 기준 |
| --- | --- | --- |
| D0 공통 기준 | 선택 13개 화면과 공통 UI | 선택 목록, 모바일 순서, 버튼/입력/모달 상태, 캐릭터·주사위 유지 조건을 정리. 기존 기능 대조표와 적용 전 화면 기준 확보. |
| D1 시작·보드 | A-1, 01-5, 02-5, 03-1 | 공통 색·글꼴·버튼과 시작 준비, 실제 게임판에 연결. 성향 확인→옵션 선택→주사위 던짐→말 도착까지 한 흐름으로 검증. 숫자뿐인 시안 주사위를 복사하지 않음. |
| D2a 상황·선택 | 04-3, 05-1, 06-2 | 시장 영향과 생활 사건을 읽고 아이콘 카드 메뉴에서 선택. 불가 버튼과 사유, X 취소·포트폴리오 조회, 남은 행동 수 유지. |
| D2b 주문·조회 | 07-5, 08-5, 09-5 | 입력과 미리보기 분할, 모바일 세로 배치. 기존 5종 주문·옵트인/아웃·보유/미결제 구분에 연결. 금액 검증과 결제 일정, 두 번째 운용 제한을 확인. |
| D3 학습·마무리 | 10-5, 11-5, 12-4 | 문제·해설, 시장/행동 분리 정산, 캐릭터 완주 화면 연결. 퀴즈 중복·스킵, 현금흐름과 운용수익 구분, 연금/일시금 비교 유지. |
| D4 전체 마감 | 설정·도움말·매뉴얼·저장·배포 | 핵심 화면의 공통 디자인을 보조 화면에도 적용. 전체 12턴, 모바일·접근성·성능·이어하기 검증 후 버전 기록/머지/운영 배포/배포 후 확인. |

D1 완료 시 첫 번째 움직이는 통합 시안을 검토하고, D2b 완료 시 주문 경험을 검토하며, D4에서 최종 운영판을 검토합니다. 이미 선택한 디자인을 단계마다 다시 고르지는 않습니다. 선택안에서 벗어나는 변경이 필요할 때만 영향과 대안을 먼저 알립니다.

## 5. 구현 방법

- 현재 `src/ui` 렌더러에 선택한 배치를 적용합니다. 디자인 자료의 HTML과 임시 클릭 스크립트를 게임 본체에 통째로 복사하지 않습니다.
- 버튼·입력·선택 카드·안내·모달·좌우 분할을 공통 스타일로 만들고, 기존 화면의 이벤트와 접근성 속성을 연결합니다. `data-action` 경로, 포커스 복귀, X 취소, 운용 횟수 차감 시점을 보존합니다.
- `GameState`, 엔진, 저장 구조는 디자인 작업만으로 바꾸지 않는 것을 기본 원칙으로 합니다. 불가피한 변경은 별도 변경 이유와 호환성 검증을 작성합니다.
- 실제 데이터는 기존 뷰 모델을 통해 읽습니다. 매수·매도·교체·리밸런싱·디폴트 거래와 정산을 계산하는 기존 엔진을 재사용합니다.
- 주사위는 현재 `renderDiceMarkup`, 시작/이동 제어, CSS 3D 연출을 재사용하고 색·그림자·크기·배경만 새 톤에 맞춥니다. 기존 SVG 보드와 말 이동 좌표/경로도 보존하는 방향으로 진행합니다.
- 모바일 분할은 CSS로 재배치합니다. 입력 도중 렌더링으로 값·커서·스크롤이 날아가지 않도록 하며, 가상 키보드와 하단 안전영역에서 확정 버튼이 가려지지 않게 합니다.
- 기존 시안 이미지는 검토용 자산입니다. 서비스에 사용할 자산의 출처·버전과 용도는 자산 목록에 함께 기록합니다.
