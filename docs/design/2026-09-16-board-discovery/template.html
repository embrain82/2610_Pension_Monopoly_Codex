01 · WHAT WE CHANGE

작은 말은 더 또렷하게.
아직 모르는 칸은 단순하게.

첨부 화면과 현재 렌더링 구조를 함께 확인했습니다. 캐릭터 원본을 다시 그리기보다 배경과의 분리, 실제 몸체 크기, 현재 위치 안내부터 개선합니다.

사용자 제공 화면

현재의 문제

캐릭터가 칸의 아이콘·번호·이름과 같은 영역을 사용합니다. 부드러운 원본 색과 그림자만으로는 밝은 칸 배경에서 충분히 분리되지 않습니다.

현재 말 컨테이너는 보드 폭의 7.8%입니다. PNG 안의 여백 때문에 실제로 보이는 몸체는 이보다 작습니다. 중앙 장식보다 말이 먼저 눈에 들어오도록 시각적 우선순위를 조정해야 합니다.

첨부 이미지가 잘린 범위만으로 실제 화면의 가로 넘침 여부는 단정하지 않았습니다.

이번 디자인의 기준

  • 원본 캐릭터 5종 유지. 색이나 얼굴을 바꾸지 않고 배지·외곽선·받침대로 강조합니다.
  • 이동은 게임답게. 실제 두 주사위, 구름·착지, 칸을 따라 이동하는 말은 유지합니다.
  • 숨기는 대상은 칸의 정체. 미공개 칸의 이름·종류·아이콘만 숨기고 경로와 번호는 보입니다.
  • 선택 조작은 늘리지 않음. 도착하면 자동으로 열립니다. 열쇠·추가 버튼·공개 비용은 없습니다.
  • 금융 판단 정보는 항상 제공. 상품·위험·금액·거래 대기·제약 안내는 가리지 않습니다.
현재 코드의 고정된 지도와 금융 엔진을 유지하는 제안입니다. 칸 공개가 새로운 수익·보상·행동 횟수를 만들지는 않습니다.
02 · TOKEN VISIBILITY

A. 내 말이 잘 보이는 5가지 방법

같은 칸과 같은 캐릭터로 효과를 비교하세요. 선택 버튼은 아래 통합 시연에만 반영됩니다. 상세 구현 방법과 완료 기준은 각 카드에서 펼칠 수 있습니다.

아래 모든 시안의 캐릭터가 함께 바뀝니다.

확대 시안에서는 형태를, 통합 시연에서는 실제 보드 대비 크기를 확인하세요. 바깥쪽 이동 좌표는 유지하고, 캐릭터 내부 크기와 장식만 조정하는 방향입니다.

모바일 크기의 현실적인 기준
390px 화면에서 몸체 약 32px, 작은 270px 보드에서는 약 26px을 목표로 실측합니다. 7칸을 한 줄에 넣으면 작은 칸의 글자를 충분히 크게 만들기 어렵습니다. 보드 아래에 ‘내 말 · 캐릭터 · 현재 칸’ 안내와 44px 이상 누름 영역의 ‘현재 칸 보기’를 제공하는 방안을 함께 권장합니다. 중앙 장식 크기는 줄여 현재 말을 우선합니다.
03 · ARRIVAL REVEAL

B. 도착하는 순간 열리는 5가지 게임판

각 안에서 주사위를 굴려보세요. 지나간 칸은 그대로 남고 최종 도착한 칸만 열립니다. 비교를 위해 모든 보드에 선택한 A1 화이트 스티커를 적용했습니다.

시연은 고정 결과 2+3 → 3+4 → 1+2를 반복합니다. 실제 게임에서는 기존 무작위 주사위를 그대로 사용합니다. 여기서는 금융 계산·저장·점수 변경이 일어나지 않습니다.

HTML/CSS 동작 시안입니다. 봉투 개봉·안개 제거·양면 카드 등 최종 연출은 아래 계획에 따라 구현하며, 시연은 공개 전후의 모양과 짧은 전환을 비교하는 용도입니다.

04 · TRY YOUR COMBINATION

선택한 두 가지를 함께 확인하세요.

A와 B를 하나씩 선택하면 이 보드에 반영됩니다. 같은 시안에서 올리·원이·단지·달리·코리를 바꾸어 가독성을 비교할 수 있습니다.

검토 선택 A1+B5 · 구현 승인 대기

A1은 캐릭터의 원형을 살린 흰 윤곽선으로 말을 강조하고, B5는 도착한 칸의 지도 스티커가 벗겨지는 방식입니다. 원이는 비교용 캐릭터이며 실제 게임의 5종 선택 기능은 유지합니다.

추가 의견 반영
도착해 공개되는 순간 이름·아이콘·고유 배경색이 함께 드러납니다. 현재 위치는 테두리로 강조하여, 말이 머무는 동안과 떠난 뒤의 칸 색상이 같습니다.

첫 이동 후 06번 운용지시의 연노랑, 두 번째 이동 후 13번 은퇴전망의 연파랑을 비교할 수 있습니다.

이 선택은 브라우저 안의 시안에만 반영됩니다. 운영 게임이나 저장된 플레이 정보에는 영향을 주지 않습니다. 새로고침하면 기록된 A1+B5 · 원이 선택으로 돌아갑니다.

05 · ONE CLEAR RULE

공개 규칙은 단순하게 고정합니다.

아래는 이번 검토 선택에 포함된 공개 규칙입니다. 운영 게임에는 아직 적용하지 않았으며 실제 구현은 별도 승인 후 진행합니다.

01 / 시작출발 칸만 공개말이 이미 서 있는 01번은 보여줍니다. 나머지 23칸에는 번호와 같은 뒷면을 사용합니다.
02 / 이동지나간 칸은 가림 유지두 주사위와 말의 점프는 유지합니다. 이동 안내는 ‘3/5칸 · 04번’처럼 번호만 읽습니다.
03 / 도착최종 도착 칸 자동 공개마지막 착지 후 0.3초 안팎으로 이름·아이콘·고유 색상을 함께 공개합니다. 열기 버튼 없이 진행합니다.
04 / 재방문열린 칸은 계속 공개말이 떠난 뒤에도 같은 색과 내용을 유지합니다. 재방문은 다시 벗기지 않고, 이어하기에서도 공개 상태를 유지합니다.

항상 볼 수 있어야 하는 정보

  • 보유자산·상품 설명·위험등급·매수/매도 가능 조건
  • 금리와 시장 변화, 손익, 위험자산 한도 안내
  • 거래 금액과 수수료 가정, 접수·기준가·결제 상태
  • 납입·연말정산 등 게임의 기본 규칙과 예정 처리
  • 성향·디폴트옵션 설명, 퀴즈 및 해설의 학습 내용

미공개 칸이 있다고 상품 메뉴 자체를 잠그거나 중요한 거래 설명을 숨기지 않습니다. 금융 모델과 교육용 가정은 이번 변경 범위에서 유지합니다.

보드 정보가 새지 않는 범위

  • 지도 선택 목록과 칸 상세창은 ‘07번 · 미공개’로 표시
  • 색·아이콘·힌트·접근성 이름에서도 칸 종류를 감춤
  • 이동 중 중앙 문구와 음성 안내에서 미공개 이름을 읽지 않음
  • 미공개 칸을 눌러도 ‘도착하면 공개’ 안내만 제공
  • ‘공개 3/24’와 기존 지역 도장은 별도 지표로 유지

이것은 화면상의 탐험 연출입니다. 고정 지도는 반복 플레이로 기억할 수 있고 코드에도 존재하므로 보안·부정행위 방지 기능은 아닙니다. 무작위 지도는 별도의 게임 균형 검토가 필요합니다.

기존 플레이와 종료 후 지도
기존 저장본은 전체 공개 상태로 유지하고 새 게임부터 적용하는 방안을 권장합니다. 12턴 종료 후 ‘전체 지도 복기’는 선택 사항으로 별도 확정합니다. 추가하더라도 조회만 허용하며 방문·점수·지역 도장을 늘리지 않습니다.
06 · IMPLEMENTATION PLAN

그림부터 바꾸고,
공개 규칙을 안전하게 연결합니다.

10개 안을 모두 제품에 넣는 계획이 아닙니다. 승인된 A·B 한 조합을 순차 반영합니다. 선택한 A1+B5 기준 약 5~7작업일을 예상하며, 1명 기준의 추정치로 선택 확정 후 재산정합니다.

D0

디자인·규칙 확정 약 0.5일

A1+B5와 공개 규칙은 검토 선택으로 기록했습니다. 도착 순간 고유 색상을 함께 드러내는 보완 시안을 확인하고 실제 게임 구현 승인을 받습니다. 종료 후 전체 지도 복기는 아직 미확정 선택 사항입니다. 390px 화면과 270px 보드에서 실제 몸체 크기·라벨 간격을 기준 이미지로 남깁니다.

산출물: 선택 조합 1개, 공통 색·테두리·그림자·크기·모션 규격, 5종 캐릭터 비교. 완료: 사용자 디자인 확인.

D1

캐릭터 식별성 먼저 적용 약 1일

기존 말 외부 컨테이너의 이동 좌표·착지 시점은 유지하고, 내부에 배지·외곽선 등 선택한 장식만 넣습니다. 캐릭터의 발·중심 좌표를 활용해 5종의 보이는 크기를 맞춥니다. 현재 칸의 장식 아이콘을 비우고 이름과 번호는 남깁니다.

수정: src/ui/token3d.ts, src/ui/avatars.ts, src/styles/characters.css, src/ui/board.ts. 완료: 전체 공개 보드에서 24개 위치의 잘림·겹침·점프를 확인한 미리보기.

D2

공개 상태와 표시 정책 통합 약 1일

새 게임에만 도착 공개 모드를 넣고, 공개된 칸은 기존 최종 도착 기록에서 계산합니다. 보드·지도 메뉴·칸 상세·화면 읽기 안내가 같은 표시 정책을 사용하게 합니다. 공개 상태의 칸 종류가 이름·아이콘·고유 배경색을 함께 결정하며 현재 위치 강조는 배경색을 덮지 않습니다. 가림을 얹는 CSS만으로 끝내지 않고 미공개 이름과 아이콘을 렌더링하지 않습니다.

수정: src/types.ts, src/engine/game-engine.ts, 신규 src/ui/board-discovery.ts, src/ui/board.ts, src/ui/route-view.ts. 완료: 출발 1칸만 공개, 숨은 이름·유형이 조회 경로로 노출되지 않음.

D3

마지막 착지와 공개 연출 연결 약 1일

마지막 이동 애니메이션을 기다린 뒤 이름·아이콘·고유 배경색을 같은 렌더 갱신에서 한 번에 공개합니다. B5 가림이 벗겨지는 부분 아래로 처음부터 해당 칸의 색이 보여야 합니다. 현재의 landed 표시만으로 마지막 착지를 판단하지 않습니다. 이동·공개 동안 중복 주사위와 운용 입력을 막고, 취소·새 게임으로 이전 애니메이션의 후속 처리가 실행되지 않게 합니다.

수정: src/ui/app.ts의 moveRolledDice()와 입력·저장 가드, 기존 애니메이션 제어기, 보드 CSS. 완료: 지나간 칸 비공개, 마지막 칸만 공개, 이미 열린 칸은 반복 연출 없음, 움직임 줄이기 지원.

D4

저장·이어하기·챕터 복기 호환 약 1일

모드가 없는 옛 저장본은 기존 전체 공개로 해석합니다. 선택 필드는 저장 검사에 명시적으로 허용합니다. 챕터 복기에서는 해당 시점의 방문 기록만 사용하여 미래에 방문한 칸이 먼저 보이지 않게 합니다. 공개 연출 중 새로고침해도 시장 계산이 두 번 실행되지 않게 확인합니다.

수정: src/ui/play-checkpoint.ts, src/engine/scenario-engine.ts, 관련 저장·턴 흐름 테스트. 완료: 기존 저장본과 새 모드의 복원·복기 결과 일치.

D5

직접 플레이·검증 후 배포 검토 약 0.5~1.5일

5종 캐릭터와 작은 화면을 우선 검증하고, 데스크톱·모바일에서 12턴을 완주합니다. 같은 시드·같은 운용 선택에서 금융 결과가 기존과 일치하는지 비교합니다. 테스트·타입·린트·빌드 통과 후 미리보기에서 최종 확인합니다.

산출물: 브라우저 검증 기록, 화면 비교, 저장 호환 결과, 금융 계산 비교. 배포: 이번에는 문서만 작성하며, 구현과 운영 반영은 사용자 확정 후 진행합니다.

중복 상태를 만들지 않는 이유

현재 route.visits는 지나간 칸이 아니라 최종 도착한 칸을 기록합니다. 이를 재사용하면 ‘공개 목록’과 ‘방문 목록’이 서로 달라지는 문제를 줄일 수 있습니다.

출발 칸은 표시 계산에만 더합니다. 기존 도장·성찰·보상 계산에는 영향을 주지 않습니다. 공개 애니메이션 중의 revealIndex는 잠깐 사용하는 UI 상태로만 둡니다.

표시용 모드 추가만을 이유로 금융 규칙 버전을 올리지 않습니다. 신규 게임 생성 시 옵션이 있는 경우에만 필드를 넣어 기존 저장 형식의 필수 키 검사를 깨뜨리지 않도록 합니다.

턴 처리 순서 — 금융 계산은 기존 위치에서 한 번

순서화면 동작상태·저장 처리
1. 주사위보드로 화면 이동 → 기존 두 주사위가 구르고 멈춤현재 턴 시작 전 저장 유지. 공개 상태를 변경하지 않음.
2. 칸 이동기존 경로를 따라 말이 이동. 지나간 칸에는 번호만 안내.이동 중 임시 위치만 바뀜. 방문·보상 계산을 추가하지 않음.
3. 최종 착지마지막 이동 Promise 완료 → 이름·아이콘·고유 색상을 적용하고 B5 가림 제거. 현재 위치는 테두리로 강조boardRevealing UI 가드 및 임시 revealIndex. 이 단계는 저장하지 않음.
4. 턴 확정공개 연출 종료 → 기존 시장·도착 사건 화면으로 이동기존 startTurn(game, steps)을 딱 한 번 실행·대입. 최종 방문 기록과 금융 결과가 함께 확정됨.
5. 저장공개된 상태에서 기존 게임 진행임시 UI 상태 해제 후 기존 체크포인트 저장. 재방문은 공개 연출만 생략.
공개 중 새로고침하면?
공개 연출은 턴 확정 전의 UI 단계로 둡니다. 그 사이 새로고침하면 기존 턴 시작 전 체크포인트에서 복원하고 같은 시드로 진행합니다. 이미 확정된 시장·급여·주문을 다시 계산하지 않도록 테스트합니다. 애니메이션 이벤트마다 startTurn()을 호출하는 구조는 사용하지 않습니다.
