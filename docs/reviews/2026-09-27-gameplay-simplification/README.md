# 연금로드 직접 플레이 리뷰 — 단순화와 게임성 개선 10가지

작성일: 2026-09-27 · 검토 기준: `main`, `460dd8e`, v1.17.0

## 결론

금융 규칙과 교육 콘텐츠는 충분히 갖춰져 있다. 다음 개선의 중심은 더 많은 설명이나 메뉴를 추가하는 것보다, **한 턴의 핵심 선택을 짧게 하고 내 선택의 결과·도전·재도전을 선명하게 연결하는 것**이다. 현재의 쉬운 행동 선택, 실제 보유분 손익 설명, 돈의 위치 그림, 주문 시간표, 분기 연습을 재사용한다.

이 문서는 구현 전 제안이다. 게임 코드와 계산식은 변경하지 않았다. 우선순위와 효과는 한 번의 관찰을 바탕으로 한 가설이며 실제 초보자 검증이 필요하다.

## 실제 플레이 범위

- Codex 컴퓨터 유즈로 로컬 `http://127.0.0.1:5173/`에서 시작 준비 → 12턴 → 수령 방식 선택 → 최종 결과까지 직접 진행했다.
- UI의 버튼·키보드·상품 선택만 사용했다. 저장 데이터를 조작하거나 엔진을 호출해 턴을 건너뛰지 않았다.
- 성향 질문은 가상 플레이용 답변이다. 사용자의 실제 투자성향을 진단한 것이 아니다.
- 안정추구형 / 저위험 사전지정 / 금리의 두 얼굴 / 월 50만원 목표 / 시드 `13s5x3-l0ot7f`.
- 추가납입, 펀드 매수·매도, 즉시 처리 예금 매수, 생활사건, 만기, 자동주문 지연·결제, 선택 퀴즈, 최종 수령 비교를 경험했다.
- 디폴트옵션 직접 매수·옵트아웃은 미리보기까지 확인했다. 직접 옵트아웃 실행·고위험 성향·위험한도 초과 주문은 이 판에서 실험하지 않았다.
- 앱 내 브라우저의 좁은 화면에서 확인했다. 실제 iPhone/Safari 터치 검증이나 다수 사용자 사용성 시험은 아니다.
- 컴퓨터 유즈의 포인터 클릭이 초기 체크박스를 바꾸지 않아 키보드 Space/Enter 조작으로 진행했다. 이 현상만으로 게임의 클릭 결함이라고 판정하지 않았다.

## 유지할 금융·거래 계약

아래는 이 저장소에서 유지할 게임 계약이다. 실제 상품의 영업일이나 개인별 세금을 게임 값과 동일시하지 않는다.

1. 생활자금, IRP 대기자금, 보유상품, 미결제 주문을 구분한다. 납입은 수익·매수와 다르고, 매도대금은 IRP 안에 남는다.
2. 성향별 허용 상품과 위험자산 한도·예외 판정을 보존한다. 예외 상품도 손실 가능성을 표시한다.
3. 현재 게임의 펀드 접수 t → 가격 t+1 → 결제 t+2와 예금·ETF 즉시 처리 가정을 유지한다. 미결제 금액 재사용을 허용하지 않는다.
4. 예금 가입 건별 약정·만기·중도해지 처리와 일반 예금/혼합 옵션 내부 예금의 구분을 유지한다.
5. 사전지정, 만기 통지·대기, 자동주문, 직접 옵트인/아웃을 구분한다. 자동운용 대상이 아닌 일반 현금을 임의로 투자하지 않는다.
6. 납입·공제한도, 중도인출 조건, 재원별 수령 계산, 마지막 주문 정산을 보존한다.
7. 미리보기·조회·취소는 행동 0회, 확정은 기존 행동 규칙을 따른다. UI를 줄여도 거래 확정을 생략하지 않는다.
8. 새로운 게임 보상은 캐릭터·지도·수집 연출에 적용한다. 수익률 가산, 결제 즉시화, 위험한도 해제, 매매 횟수 보너스로 연결하지 않는다.

## 개선사항 10가지

### 1. 시작 준비를 한 흐름으로 압축한다 — P1

**관찰:** 첫 주사위 전에 안내·진단 진입·5문항·결과 확인·옵션 선택 화면이 이어졌다. 첫 게임 행동을 경험하기 전에 읽기와 확인에 머문다.

**제안:** 성향 5문항과 결과 확인은 유지하되 진단 진입 전 중간 화면을 합친다. 결과 요약과 옵션 선택을 한 준비 화면에 배치한다. 긴 게임 방법은 첫 턴 해당 조작 옆에서 한 줄씩 등장하게 한다. 시작 구성·성향·사전지정은 최종 버튼 앞에서 명확히 확인한다.

**기대 경험:** 처음부터 규칙을 외우지 않아도 바로 첫 선택에 도달한다.

**보존:** 실제 판에서 진행하는 첫 행동임을 표시하며 숨은 연습이나 자동 거래를 넣지 않는다. 성향 진단·선택 동의를 생략하지 않는다.

**검증 기준:** 첫 주사위까지 불필요한 중간 확인을 2회 이상 줄이고, 사용자가 시작 성향과 선택 옵션을 설명할 수 있는지 확인한다.

**구현 후보:** `src/ui/start-preparation.ts`, `quick-guide.ts`, `guided-practice.ts`.

### 2. 기본 HUD는 목표 하나와 두 지갑에 집중한다 — P0

**관찰:** 목표·별 조건·학습점수·지역 도장·물가·TDF 비중·잔액 증가율이 함께 등장한다. 7턴까지 2/3 조건을 충족해도 0별, 8턴에 3별로 바뀌었다. 마지막에는 목표 50만원 달성이지만 세후 수령액은 499,929원이었다.

**제안:** 기본 영역은 `은퇴 목표 49.2/50만원(세전 게임 목표)`, `생활 지갑`, `IRP 주문 가능액`을 중심으로 정리한다. 생활 안정·낙폭은 작은 상태 표시로 남기고 상세 수치·학습·수집은 별도 펼침에서 본다. 별은 최종 평가이며 현재 달성은 잠정 상태라는 점을 명확히 한다. 결과에서는 세전 목표와 세후 수령액을 바로 나란히 보여준다.

**게임성:** 수치가 늘어나는 의미와 남은 거리를 한눈에 파악하게 한다. 최종 별 산식을 유지하면서 중간 목표 달성에 짧은 연출을 준다.

**검증 기준:** 사용자가 5초 안에 현재 목표·부족분·바로 쓸 돈을 찾는다. 세후 50만원 달성으로 오해하지 않는다.

**구현 후보:** `hud.ts`, `play-scene.ts`, `learning-progress.ts`, `result-summary.ts`.

### 3. 한 턴을 하나의 흐름으로 묶고 선택 퀴즈의 재확인을 줄인다 — P0

**관찰:** 행동→정산→다음 턴 준비→퀴즈 건너뛰기 확인→보드→주사위 순서가 반복된다. 8턴에는 한 문제를 맞힌 뒤에도 남은 다른 퀴즈 때문에 확인창이 다시 나타났다.

**제안:** 보드 옆/아래 한 패널을 `상황 → 내 선택 → 결과` 순서로 바꾼다. 정산에 `한 문제 도전`과 `다음 턴`을 동등하게 두고, 다음 턴은 선택 학습을 건너뛰는 뜻임을 버튼 근처에 명시한다. 여러 문항은 복습 메뉴에 남기고 매 턴 건너뛰기 팝업을 반복하지 않는다. 마지막 종료에서 미응답 학습의 처리만 짧게 알려준다.

**보존:** 만기 통지·위험한도 경고·실제 거래 확정은 선택 퀴즈와 다르게 필수 정보로 유지한다. 다음 주사위를 자동으로 굴리지 않는다.

**검증 기준:** 거래 없는 일반 턴의 불필요한 화면 전환·확인 횟수를 줄이고, 퀴즈 참여율과 완주율을 함께 측정한다. 기존 퀴즈 확인 정책을 바꾸는 구현이므로 관련 테스트의 기대 동작도 명시적으로 갱신한다.

**구현 후보:** `app.ts`, `settlement.ts`, `turn-notices.ts`, `quiz-view.ts`.

### 4. 거래 화면을 상품·금액·결과 한 장으로 줄인다 — P0

**관찰:** 매수 화면에 종류 5개, 용어, 지시 입력, 돈 위치 그림, 거래 미리보기, 시간표, 보수 설명이 길게 이어졌다. 좁은 화면의 첫 화면에는 확정 버튼이 보이지 않았다. `기본 100만원` 표시와 실제 1,001,000원 요청처럼 축약 금액도 구분이 필요했다.

**제안:** 상단에 상품 비교 카드(위험, 돈이 묶이는 기간, 역할)와 정확한 주문 금액을 배치하고 하단에 `이 금액이 어디로 가는지 / 언제 완료되는지 / 남는 돈`을 한 번만 요약한다. 초보용 금액 선택은 `일부·절반·가능액`처럼 실제 계산 기준을 명확히 하고 각 버튼에는 정확한 실행액을 병기한다. 확정 버튼은 스크롤 하단에 고정하되 핵심 확인 내용도 함께 보이게 한다.

**보존:** 즉시 거래와 대기 주문, 일반 상품과 옵션 묶음, 비용·위험·한도·만기 경고를 생략하지 않는다. 상세는 펼침으로 접근 가능하게 둔다.

**검증 기준:** 확정 전 사용자가 상품·금액·결제 시점·생활자금 변화 여부를 말할 수 있다. 기존 엔진의 미리보기와 실행 결과가 일치해야 한다.

**구현 후보:** `action-form.ts`, `trade-preview.ts`, `money-flow.ts`, `default-trade-view.ts`.

### 5. 주문과 자동운용을 하나의 진행표로 설명한다 — P0

**관찰:** 5턴 예정 자동운용이 기존 펀드 환매 결제로 지연됐다. 6턴 자동주문에서는 예금은 보유분, TDF는 8턴 결제 대기로 나뉘었다. 현재 시간표가 이미 있지만 주문/만기/포트폴리오 여러 곳을 오가며 전체 흐름을 읽어야 했다.

**제안:** 항상 같은 위치에 `진행 중인 일` 카드를 두고, 다음 한 단계와 이유를 우선 표시한다. 예: `장기채 매도대금: 6턴에 IRP 현금으로`, `자동운용: 기존 주문 결제를 기다리는 중`, `예금 완료 / TDF 8턴 완료 예정`. 더 펼치면 기존 상세 시간표를 본다.

**게임성:** 기다리는 시간이 막힘으로 느껴지지 않고 다음 턴에 확인할 목표가 된다. 단계 완료에 짧은 돈 이동 연출을 붙인다.

**보존:** 화면의 연출만 바꾸며 결제일을 당기거나 미결제 금액을 다시 사용하지 않는다. 사전지정과 주문은 별개로 표시한다.

**검증 기준:** 포트폴리오 전체를 열지 않고도 다음 결제와 지연 이유를 설명한다. 이번 플레이의 4→5→6→8턴 흐름으로 회귀 검증한다.

**구현 후보:** `order-timeline.ts`, `maturity-view.ts`, `default-checkpoint.ts`, `portfolio-view.ts`.

### 6. 정산을 ‘내가 한 일 → 지금 결과 → 다음 변화’로 보여준다 — P0

**관찰:** 실제 예금/채권 손익 원인과 입출금 분리는 이미 잘 구현되어 있다. 그러나 2턴 펀드 주문 후 대표 학습 문장은 `새 거래가 없어도…`였고, 6·8턴에 첫 행동을 실행한 뒤 남은 행동을 마감하면 끝 문장은 `이번 턴은 행동하지 않고…`였다.

**제안:** 현재 실제 원장 분해를 유지하고 그 위에 이 턴의 행동 카드를 놓는다. `장기채 주문 100.1만원 접수 → 지금은 처리 중 → 4턴 보유 반영`, `200만원 납입 → 대기자금 증가 → 매수는 아직 안 함`처럼 작성한다. 2회 행동 턴은 수행한 첫 행동과 남은 행동 마감을 함께 요약한다. 변화가 없는 항목은 펼침으로 옮긴다.

**게임성:** 숫자를 읽는 보상보다 자기 선택이 반영되었다는 보상을 준다. 시장 손익을 자신의 매매 실력으로 오인하게 하지 않는다.

**검증 기준:** 주문 접수·기존 주문 결제·납입·유지의 문장이 실제 턴 기록과 맞는다. 이미 완료된 주문을 무조건 `처리 중`으로 설명하지 않는다.

**구현 후보:** `settlement.ts:144`, `settlement-view-model.ts`, `return-explanation.ts`, `market-impact-view.ts`.

### 7. 기존 12턴을 짧은 이야기와 단계 도전으로 연결한다 — P1

**관찰:** 기존 장·분기 기능은 있지만 기본 진행에서는 시장·상품 안내가 중심이다. 8턴에 3별 조건을 달성한 뒤에도 다음 권유는 상품 탐색이 주로 나왔다.

**제안:** 기존 4장/3턴 구조를 사용해 `돈의 위치 익히기 → 주문 기다리기 → 충격에 대응하기 → 은퇴 선택하기`처럼 한 장에 목표 하나만 전면에 둔다. 목표 달성 후에는 `남은 턴 동안 생활자금과 목표 지키기`로 안내를 바꾼다. 특정 매매를 정답으로 강제하지 않고 유지 선택도 맥락에 맞게 인정한다.

**게임성:** 12번 비슷한 창을 처리하는 느낌을 줄이고 시작·고비·성취·마무리의 리듬을 만든다. 보상은 캐릭터 반응/여행 앨범에 제한한다.

**보존:** 장 안내를 위해 만기·가격·시장을 임의로 다시 처리하지 않는다. 새 필수 금융 조건이나 매매 횟수 보너스를 넣지 않는다.

**검증 기준:** 플레이어가 현재 장의 목표를 한 문장으로 말한다. 목표 달성 후 남은 턴의 이탈률을 비교한다.

**구현 후보:** `campaign-view.ts`, `action-guidance.ts`, `token-emotion.ts`, `speech.ts`.

### 8. 보드 탐험에 작은 선택권과 수집 목표를 준다 — P2

**관찰:** 미지의 칸은 흥미 요소지만 이동은 주사위 합으로 정해진다. 1·9턴은 매수할 수 없는 ETF, 5·10턴은 직접 매수 불가 TDF가 스포트라이트로 나왔다. 도착과 내 운용 선택의 연결이 약했다.

**제안:** 우선 금융 이동 규칙을 그대로 두고, 장 시작에 `이번에 알아볼 지역/주제`를 선택하게 한다. 작은 지도 단서나 칸의 역할 미리보기로 탐험 목표를 갖게 하고, 그 주제를 이해하면 캐릭터 소품/앨범을 얻는다. 아직 방문하지 않은 칸의 실제 발견 도장과 사전 열람을 구분한다. 매수 불가 상품의 칸에서는 강제 매수 대신 해당 상품의 차이를 이해하는 도전을 준다.

**게임성:** 보드에서 무엇을 발견할지 기대하고 선택할 이유가 생긴다. 수집 자체가 금융 수익을 바꾸지는 않는다.

**보존:** 시장의 미래 정답 공개, 주사위 재추첨으로 사건 회피, 상품 매수 보상, 수익률·한도 특혜를 주지 않는다. 이동 경로 변경은 이번 우선 제안에서 제외한다.

**검증 기준:** 사용자가 선택한 탐험 목표를 기억하고 도착 시 의미를 느끼는지 확인한다. 동일 금융 입력에서 계좌·시장 결과는 기존과 같아야 한다.

**구현 후보:** `board-discovery.ts`, `tile-briefing.ts`, `tile-effects-view.ts`, `route-view.ts`.

### 9. 생활사건을 ‘긴 설명의 선택창’에서 캐릭터의 연속 이야기로 바꾼다 — P1

**관찰:** 2·10턴에 같은 이직 준비 사건이 반복됐다. 이 사건에서는 생활자금만 가능하고 나머지 두 큰 선택은 비활성화였다. 5턴 의료비도 미결제 주문 때문에 인출 선택이 막혀 실제로 선택 가능한 것은 하나였다.

**제안:** 실제 선택 가능한 행동이 하나면 해결 행동을 크게, 불가능한 방법은 `왜 IRP를 못 꺼내나요?`라는 짧은 이유 영역으로 합친다. 선택 가능한 사건은 `지금 돈 / 나중 목표` 두 결과를 나란히 비교한다. 동일 경제 규칙을 유지하면서 사건의 대사·후속 장면은 이전 선택을 기억하게 만든다. 생활자금을 남겨둔 판단이 이후 사건에서 어떤 역할을 했는지 캐릭터가 구체적으로 반응한다.

**게임성:** 의미 없는 비활성 선택지를 줄이고 내 선택이 이어지는 이야기를 만든다. 난이도는 무작위 비용 증폭보다 후속 결과의 이해에서 만든다.

**보존:** 법정 사유가 아닌 인출을 새로운 재미 요소로 허용하지 않는다. 사건의 비용·급여·세금·결제 제한은 바꾸지 않는다. 새로운 비용 선택지를 추가한다면 별도 밸런스 변경으로 검토해야 한다.

**검증 기준:** 사용자가 가능한 행동과 제한 이유를 즉시 구분하고, 다음 사건에서 자신의 과거 준비와 연결해 설명할 수 있다.

**구현 후보:** `life-view.ts`, `speech.ts`, `token-emotion.ts`, 생활사건 콘텐츠.

### 10. 결과의 중심을 ‘점수’에서 ‘한 가지 바꿔 다시 해보기’로 옮긴다 — P1

**관찰:** 결과는 3별·88점·도장 4개로 잘 정리되지만 성공 후 첫 재도전은 일반적인 `새 시드로 도전`이다. 실제 선택 기록, 비교 지수, 3/6/9턴 분기는 상세 안쪽에 있다. 내 IRP가 고스트보다 크지만 전체 자금 비교는 달라 비교 기준을 쉽게 오해할 수도 있다.

**제안:** 상단에 이번 판의 결정적 순간 2~3개를 보여준다. 예: `4턴 충격을 어떻게 넘겼나`, `7·8턴 납입으로 목표 도달`, `생활비를 IRP 밖에서 해결`. 그 아래 `3턴 끝에서 다른 선택 실험`과 `다른 시장 도전`을 둔다. 기존 분기 기능을 재사용하고 선택 하나를 바꾼 차이를 비교한다. 세전 목표·세후 수령액을 같은 카드에서 설명한다.

**게임성:** 이미 성공한 사용자도 다른 선택의 결과가 궁금해진다. 실패자는 막연한 재시작 대신 한 가지를 바꿔 볼 수 있다.

**보존:** 단순 고스트 차이를 투자 실력으로 단정하지 않는다. 동일 입출금 기준 지수와 생활 선택이 다른 고스트를 구분한다. 이미 본 미래를 활용한 분기 연습은 첫 플레이 기록과 분리한다.

**검증 기준:** 결과를 본 사용자가 자신의 선택 하나와 그 영향을 설명하고, 재도전을 실행하는 비율을 측정한다. 기존 분기·수령 재비교의 완주 횟수 중복 방지 검증을 유지한다.

**구현 후보:** `result-summary.ts`, `retry-view.ts`, `campaign-view.ts`, `learning-progress.ts`, `app.ts:1635`.

## 실행 순서와 검증

1. **먼저 2·3·4·5·6:** 계산식을 건드리지 않고 정보량·왕복·상태 설명부터 개선한다. 초보자는 ‘현재 돈, 지금 행동, 다음 결과’를 이해하는 것이 먼저다.
2. **다음 1·7·9·10:** 시작, 장별 도전, 사건 이야기, 재도전을 연결한다. 기존 기능을 전면 배치하는 것이 우선이다.
3. **마지막 8:** 탐험 선택과 장식적 수집을 작은 실험으로 추가한다. 화면을 다시 복잡하게 만들면 축소한다.

후속 구현에서는 같은 시드와 같은 금융 행동을 재생해 원장·주문·결제·만기·세금·최종 별/점수가 유지되는지 확인한다. UI 변경으로 의도한 행동·퀴즈 흐름만 바뀌는 부분은 따로 검증한다. 지금 문서 작성에는 게임 코드를 바꾸지 않았으므로 테스트를 재실행하지 않았다.

초보자 소규모 검증의 핵심 질문은 세 가지다: “지금 쓸 수 있는 돈은?”, “방금 한 행동으로 무엇이 변했나?”, “다음 턴 무엇을 기다리나?” 여기에 첫 선택까지의 입력 수, 의미 없는 확인 수, 완주율, 재도전율을 함께 기록한다. 목표 수치는 구현 후 사전 정의하며 이번 단일 플레이로 개선 효과가 입증됐다고 말하지 않는다.
