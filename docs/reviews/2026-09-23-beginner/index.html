구현 방향

현재 공개된 시장 정보와 실행 가능 판정을 함께 사용합니다. 미래 시장·수익률을 예측하거나 특정 상품의 수익을 약속하지 않습니다. 버튼은 미리보기만 열고 거래를 자동 실행하지 않습니다. 기존 IRP 대기자금으로 예금을 사는 것만으로 위험자산 비중이 낮아진다고 안내하지 않도록 산식을 점검합니다.

금융 설명 검토 기준: 하나은행 개인형 IRP 핵심설명서의 투자성향·손실 가능성·위험자산 한도 및 예외. 규정상 위험자산 비중과 상품의 실제 가격 변동 위험은 구분합니다.

완료 조건 · 제안 목표

같은 자금·주문 상태에서는 힌트와 버튼 가능 여부가 일치해야 합니다. 행동 2회 턴의 첫 행동 후에는 다시 계산합니다. 추가납입을 운용 수익으로, 70% 한도 내라는 이유를 손실 없음으로 설명하지 않아야 합니다.

운용 메뉴에는 여러 거래와 비활성 이유가 한꺼번에 보입니다. 만기 통지까지 붙은 모바일 화면에서는 실제 행동 버튼이 첫 화면 밖으로 밀려났습니다.

화면 문구 예시

“은퇴자금 더하기” / “대기자금으로 상품 살펴보기” / “이번 턴 그대로 두기”. 처리 중인 주문이 있으면 “주문 진행 확인”을 우선 보여줄 수 있습니다.

구현 방향

5번 힌트와 같은 판단 결과를 사용합니다. 숨겨진 강제 추천이나 자동 선택을 만들지 않고, 전체 메뉴 접근을 항상 제공합니다. 그대로 두어도 기존 주문 결제나 예정된 자동운용이 진행될 수 있음을 상태별로 표시합니다.

완료 조건 · 제안 목표

첫 화면에서 선택 가능한 목적과 전체 메뉴 입구가 분명해야 합니다. 전체 메뉴의 기능·카드 디자인·취소 동작·행동 횟수는 유지하며, 장애가 있는 행동을 추천 카드로 제시하지 않아야 합니다.

주문 미리보기와 주문 내역에 동일한 세 단계 시간표를 둡니다. 각 단계에 돈의 상태와 지금 할 수 있는 일을 붙이고 정식 용어는 함께 남깁니다.

펀드 미리보기는 접수 2턴 → 기준가 3턴 → 결제 4턴을 정확히 보여줍니다. 초보자는 “샀는데 왜 아직 처리 중인가”와 사용 가능 금액을 함께 이해해야 합니다.

화면 문구 예시

“지금: 주문 금액을 따로 잡아둬요 · 접수 → 다음 턴: 매수가격이 정해져요 · 기준가 확정 → 그다음 턴: 보유 상품에 반영돼요 · 결제”

구현 방향

실제 주문 엔진의 일정과 상품별 처리 방식을 사용합니다. 모든 상품이 같은 기간이라고 일반화하지 않습니다. 상품 비용, 가격 변동과 손실 가능성, 이미 주문에 묶인 금액은 확인 화면에서 계속 보여줍니다.

완료 조건 · 제안 목표

접수·가격 확정·결제 이후 강조 단계와 잔액이 일치해야 합니다. 주문 금액을 다시 쓸 수 있다고 오해하게 하지 않아야 하며, 표시된 턴 수가 게임의 압축 규칙임을 구별할 수 있어야 합니다.

사전지정부터 만기·통지·자동운용까지 한 줄로 이어줍니다.

기존 안내를 “현재 단계 / 해당 금액 / 다음 예정 행동과 시점”으로 압축합니다. 상세를 열면 단계 연결과 직접 운용 방법을 볼 수 있게 하고, 같은 경고 카드를 반복 추가하지 않습니다.

직접 관찰 / 검토

사전지정과 실제 보유 구분, 예금 만기 대기·통지·자동운용 안내는 이미 있습니다. 여러 금액과 긴 설명이 운용 메뉴 위에 놓이면 당장 해야 할 행동이 아래로 밀립니다.

화면 문구 예시

“만기자금 6,593만원 · 통지 확인 단계. 운용지시가 없으면 게임 5턴에 사전지정한 저위험 옵션으로 주문할 예정이에요.” 금액과 턴은 실제 상태에서 계산합니다.

구현 방향

사전지정·대기·통지·주문·보유를 하나의 상태 표시로 연결합니다. 새로 납입한 일반 대기자금 전체가 만기 자동운용 대상처럼 보이지 않게 합니다. 직접 운용지시가 적용되는 범위와 진행 중인 주문을 기존 엔진 기준으로 설명합니다.

제도 근거: 금융위원회 사전지정운용제도 설명. 만기 후 운용지시 없이 4주 경과 → 통지 → 추가 2주 경과의 절차와 게임 내 압축된 턴 일정을 구분해 설명합니다.

완료 조건 · 제안 목표

만기 대상 금액, 통지 여부, 예정 턴, 실제 주문 상태가 맞아야 합니다. 짧은 요약만 읽어도 “무슨 돈이 언제 어떻게 되는지”를 알 수 있어야 합니다. 법정 대기기간과 게임 턴의 압축 표현을 구분합니다.

P1 연결 경험 보완

목표와 정산은 핵심부터, 승리 조건은 명확하게

이번 선택의 결과를 짧게 이해한 뒤 상세로 들어갑니다.

보드에는 주 목표와 필수 조건을 짧게 묶습니다. 정산 상단은 시장 손익 / 내 납입·출금 / 주문·정산 영향과 “이번 턴 배운 한 가지”를 보여주고 비교·도장 해석은 상세로 둡니다. 최종 목표 미달 때도 잘한 판단 한 가지와 다음 시도 한 가지를 바로 읽게 합니다.

관찰 · 문구 · 구현 방향 · 완료 조건 보기 ＋

직접 관찰 / 검토

연금 목표와 함께 생활자금·낙폭·도장·발견·챕터·비교 지수 등 여러 지표가 등장합니다. 첫 정산은 상세를 접은 상태에서도 약 2.7개 모바일 화면 길이였습니다. 완주 결과는 목표 월 환산액 469,053원 / 목표 500,000원, 별 0개였지만 생활자금·낙폭 조건은 충족했습니다.

화면 문구 예시

“이번 턴 IRP가 169만원 늘었어요. 시장 영향 약 69만원 + 내가 넣은 돈 100만원이에요. 납입은 수익률과 다른 변화예요.”

구현 방향

기존 원장과 손익 구분을 유지하고 한 줄 정리를 접힌 상세 밖으로 옮깁니다. 주 목표에 도달해도 생활자금·낙폭 등 실제 승리 조건을 숨기지 않습니다. 별·도장·수익 계산은 바꾸지 않습니다. 결과 화면의 기존 성과·수집·다시 연습은 유지하면서 목표용 월 환산액, 선택한 방식의 세후 월 수령액, 학습 점수의 기준을 나누어 설명합니다.

완료 조건 · 제안 목표

정산 첫 화면에서 증가 원인을 구별하고 필수 목표 충족 여부를 확인할 수 있어야 합니다. 모든 합계가 기존 상세와 맞고, 상세에서 비교 지수와 지역 도장 내용을 계속 확인할 수 있어야 합니다.

뜻보기에서 한 개념을 그림이나 다른 숫자 예시로 설명한 뒤, 퀴즈에서는 별도의 상황에 적용하게 합니다. 정답 문장을 그대로 먼저 보여주는 구조는 피합니다.

직접 관찰 / 검토

현재 퀴즈는 이미 상황형이며 선택 학습이고 오답 벌점도 없습니다. 다만 납입한도·세액공제한도 같은 개념을 처음 만나는 사람에게는 판단 근거가 아직 없을 수 있습니다.

구현 방향

개념 카드와 퀴즈를 같은 주제로 연결하되 예시와 보기 문장은 분리합니다. 오답 벌점 없음과 선택 학습을 유지합니다. 반복되는 건너뛰기 경고의 빈도를 줄일지는 별도 검토·확정 항목으로 남깁니다.

설명과 정답의 개념이 일치하면서도 그대로 복사한 문장 찾기가 되지 않아야 합니다. 퀴즈를 풀지 않아도 게임을 계속할 수 있고, 기존 점수·도장 규칙에 의도하지 않은 변화가 없어야 합니다.

04 · IMPLEMENTATION ORDER

함께 움직여야 하는 것부터 구현합니다.

힌트와 선택 메뉴가 서로 다른 말을 하지 않도록 같은 판단 기준을 사용합니다. 아래 순서는 구현 승인 후 적용할 제안입니다.

① 네 컷 + ③ 돈 흐름

⑤ 힌트 + ⑥ 선택 메뉴

묶음 3 · P1

② ④ ⑦ ⑧

첫 두 턴 실습, 쉬운 말, 주문 시간표, 자동운용 상태를 연결합니다.

묶음 4 · P1

⑨ 정산 + ⑩ 학습

내 선택의 결과를 이해하고 다음 상황에 적용하게 합니다.

최종 확인은 “설명을 읽었는가”보다 “이해하고 선택했는가”

  • 퇴직연금을 잘 모르는 참여자가 도움 없이 게임의 네 단계와 목표를 설명할 수 있는지 봅니다.
  • 첫 두 턴 뒤 생활자금·대기자금·상품·처리 중 금액을 구별하는지 확인합니다.
  • 첫 결정까지 걸린 시간, 막힌 지점, 뜻보기 사용, 의도하지 않은 확정을 기록합니다. 아직 측정한 성과 수치는 없습니다.
  • 동일한 게임 상태에서 안내 전후의 이해도를 비교합니다. 수익이 높아졌다는 이유만으로 안내가 좋아졌다고 판단하지 않습니다.
