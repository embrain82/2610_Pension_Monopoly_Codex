## 근거별 관찰

1. `03-default-choice.txt`, `04-first-board.txt`: 기본 규칙 안내는 접힌 상세에 있고 시작 후 바로 보드에 진입했다. 코드 점검에서도 시작 준비 확정 시 `howtoSeen=true`가 설정되는 것을 확인했다.
2. `05-turn1-arrival.txt`: 생활자금이 있어도 IRP 대기자금이 0원이면 매수할 수 없음. 계좌 간 관계를 읽고 연결해야 한다.
3. `06-turn1-settlement.txt`: 모바일 정산 모달의 표시 높이 약818px에 내용 높이 약2,202px. 기존 코치의 한 줄 정리와 다음 판단은 닫힌 상세 안에 있었다. 접근성 스냅샷에는 접힌 내용도 포함되므로 별도로 details.open을 확인했다.
4. `07-quiz.txt`: 현재 퀴즈는 상황형이며 오답 벌점이 없고 정답 해설이 있다. 제안은 퀴즈 최초 도입/전면 교체가 아니라 설명→적용 순서 개선이다.
5. `10-fund-preview.txt`, `12-portfolio.txt`: 펀드 주문·결제 대기와 만기자금이 겹쳐 여러 금액 범주를 동시에 읽어야 한다.
6. `13-turn4-notice.txt`, `14-second-action.txt`, `mobile-menu.png`: 만기 안내가 이미 있으나 길이가 길다. 390×844 캡처에서 실제 운용 선택은 첫 화면 아래로 밀렸다. 이미지 파일도 열어 시각 확인했다.
7. `15-turn5-auto.txt`, `16-turn7-default-holding.txt`: 사전지정과 실제 보유가 다른 상태에서 자동주문·결제 완료로 이어지는 과정 확인.
8. `19-final-settlement.txt`~`21-result.txt`: 목표용 환산액, 세후 수령액, 별, 보조 점수, 수집 기록의 기준이 다양하다. 한 가지 핵심 목표와 주의 조건을 먼저 읽도록 제안한다.

## 코드 점검에서만 확인한 사항

- `src/ui/app.ts:1152`: 시작 준비 확정에서 게임 방법을 본 것으로 기록.
- `src/ui/settlement.ts`: 기존 한 줄 코치/다음 판단이 상세 영역에 배치됨.
- `src/engine/settlement-engine.ts:7`: 한도 초과 힌트의 '예금·채권으로 대기자금을 옮기거나 리밸런싱' 표현은 허용되는 추가매수와 실제 위험비중 감소를 혼동하게 할 수 있음. 기존 IRP 대기자금으로 예금을 매수하는 것만으로 위험자산 비중이 감소하지는 않음. 이번 안정추구형 경로에서 70% 초과 상황은 직접 재현하지 않았음.
- 행동 가능 여부, 성향·위험 제한, 미결제 여부를 판정하는 기존 엔진을 코치에도 재사용할 수 있음.

## 검토의 한계와 다음 검증

이 검토는 한 사람이 브라우저 도구로 수행한 UI 플레이와 코드 분석이다. 실제 초보자들의 이해도 개선을 측정한 결과는 아니다. 제안 승인·구현 후에는 퇴직연금 초보자 5명 정도에게 '게임 순서 설명하기 / 돈이 있는 위치 찾기 / 첫 운용 선택하기 / 기다리는 주문 설명하기'를 수행하게 하고, 도움 요청 횟수와 오해를 기존 화면과 비교하는 것이 좋다. 보고서의 완료 조건은 제안 목표이며 이미 통과한 결과가 아니다.
