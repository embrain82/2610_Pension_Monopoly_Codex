# 2026-09-29 개선사항 접수 및 원인 분석

대상: FB-042~045. 이 요청은 개선사항 추가와 분석/수정방안 제안이다. 점수 오류가 있으면 수정하라는 조건도 확인했으나 점수는 현재 규칙과 일치한다. 이번 작업에서 게임 코드·점수 정책·운영 배포를 변경하지 않았다.

## FB-042 · 전체 평가금액과 손익

운용창의 주문 가능 IRP/생활자금 요약에 전체 IRP 평가액 및 부호 있는 누적 운용손익을 제안한다. 전체 IRP는 portfolioValue의 보유+대기+미결제 값이다. 생활자금은 합산하지 않는다. 손익은 시작 IRP와 순입출금을 제거한 금액으로 정의하고, 세금·중도인출 등의 cashFlows 반영을 기존 회계 테스트와 대조한다. 캠페인 운용지수 변화에 현재 잔액을 곱하는 방식은 사용하지 않는다. 제목에 ‘납입 제외 누적 운용손익’을 명시한다. 상단 기존 자금 항목 및 폰트 크기는 유지한다.

## FB-043 · 미응답인데 학습 4/20점

scoring-engine.ts KNOWLEDGE_CAPS.base=4. knowledgeBreakdown은 기본 4 + 퀴즈 + 이해 + 리밸런싱 - 위반을 0~20으로 제한한다. 캠페인 판은 이해·리밸런싱 가산 0, 퀴즈는 정답당 2점 최대16점이다. 새 캠페인 정답0개→퀴즈0점→총4점 테스트 통과.

따라서 오류는 계산이 아니라 기본점수의 설명 부재다. learning-progress.ts는 상세에도 퀴즈 기여만 표시한다. 권장안은 점수 규칙을 바꾸지 않고 ‘학습 4/20점 · 시작 기본 4점 · 퀴즈 획득 0/16점(정답0개)’로 구성 근거를 보여주는 것. 0점 시작 정책으로 바꾸면 최종 100점 배점 및 구 저장 호환을 함께 설계해야 한다.

## FB-044 · 현재 턴

ongoing-view.ts의 ‘진행 중인 일’ 제목에 ‘현재 5/12턴’처럼 현재 game.turn을 추가한다. 여러 주문마다 반복하기보다 공통 제목에 표시하고 접수/기준가/결제 일정은 유지한다. 턴이 변경되면 같은 game state로 동시에 갱신한다.

## FB-045 · 생활사건 선택창 누락

### 확인된 코드 경로

- 정상 경로: afterMarketScene/nextQuiz는 currentEventId가 남으면 life 창으로 보낸다.
- closeModal: 포트폴리오의 운용 복귀 플래그가 없거나 시장·설정 등 일반 조회창이면 modal=null로 끝날 수 있다. 남은 생활사건 복귀 처리가 없다.
- resumeGame: 저장 modal을 그대로 복원한다. currentEventId가 있는데 modal=null인 기록을 자동 복구하지 않는다.
- renderGameCta: currentEventId가 있으면 ‘생활사건 해결 중’을 disabled로 출력한다. 창을 잃으면 다시 열 수 없다.
- syncArrivalScene: arrivalPending=false이면 자동 재진입하지 않는다.

첨부4의 ‘생활사건 해결 단계/비활성 버튼/선택창 없음’은 이 상태와 일치한다. 다만 첨부만으로 최초 누락 원인을 특정할 수는 없다.

### 상태 전이 재현 결과

happy-dom 검사 5개 통과(reproduction.log). 기본 4점 확인 1개, 사건 중 portfolio/market/settings로 바뀐 후 닫기 3개, 미해결 사건+modal=null 저장 이어하기 1개.

조회창 전환 검사에서는 배경 버튼의 click을 직접 호출했다. 실제 브라우저에서 모달 뒤 버튼을 사용자가 클릭할 수 있다는 증거는 아니며, 해당 상태 전이가 발생했을 때 복귀·회복이 없음을 입증한다. 사용자 조작 전체를 재현한 결과로 해석하지 않는다. 저장 복원 테스트 역시 구성한 유효 기록이며 사용자의 실제 저장 파일은 읽지 않았다.

### 권장 수정안 · 우선순위 P0

1. 사건이 남아 있고 선택창이 닫혀 있으면 하단에 활성 ‘생활사건 선택하기’ 버튼을 제공한다. 클릭은 창만 열며 금융/시장 처리를 재실행하지 않는다.
2. 조회창을 닫으면 현재 남은 진행 단계로 돌아가도록 공통 복귀 함수를 둔다. 도착 공개·뉴스·퀴즈 순서를 건너뛰지 않도록 기존 분기를 존중한다.
3. 이어하기에서 미해결 사건+modal=null+arrivalPending=false이면 life로 복원한다. 도착 대기가 남았으면 기존 도착 경로를 유지한다.
4. 사건 선택 실패는 사유와 창을 유지하고 성공 시 currentEventId 해제 후 기존 운용 진입. 이중 클릭/복귀로 비용·급여·시장 변동을 다시 처리하지 않는다.

완료 기준: 직접 버튼 복구, 조회창 왕복, 새로고침/이어하기, 배경 전환, 효과 켬/끔, 충격 속보+사건, 퀴즈+사건, 자금 부족, 사건 해결 후 복귀를 검사한다. 금융 상태 동일성과 사건 처리 1회를 확인한다. 우선 P0 사건 복구, 그다음 금액/점수 설명/현재 턴 표시를 권장한다.
